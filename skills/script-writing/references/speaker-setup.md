# Speaker setup

Builds `speakers/<name>.md`: how one person talks on camera. Done once per
speaker, then grown by learning (`learning.md`). Run it when a new speaker
joins, or when a script is asked for and the speaker has no file.

## Read what exists

Anything this person has said or written in their own words, best first:
1. **Past scripts with their edits:** a generated draft next to their
   edited version shows exactly what they change.
2. **Transcripts** of their videos, talks or calls.
3. Posts or emails they wrote themselves.
4. Notes about how they talk, from them or their team.

Ask the human where these are. Don't use material written for them by
someone else as evidence of their voice.

## Draft the file

Use the format in `../content-ideation/references/workspace.md`,
*speakers/<name>.md* (template: `../content-ideation/templates/speaker.md`).
Its sections are Stance · Phrases they use · How they open · How they close
· Numbers · Signposts · Always cut · Never say · Examples (before → after).

- **Every rule is backed by a quote** from the material, with where it came
  from. No quote, no rule.
- Keep a rule here only if it's this person's habit. A rule that would hold
  for any speaker belongs in craft; a word the whole industry uses belongs
  in `niche-words.md` (propose it there).
- Where two sources disagree (an old note says one thing, a recent edit the
  opposite), don't choose. List the conflict for the speaker to settle.
- The first line is `Built from: <sources>, <YYYY-MM-DD>`.

## Review

The speaker reads the draft and corrects it. From then on this file is the
source of truth for how they talk; the material it came from stays as
history, and learning writes only to this file.

Named example: for Tars, the founder's file starts from his own voice notes
and the rules found by comparing his edits with five generated drafts.
